# 多语言（i18n）

Aurora Music 的语言支持是**底层能力**，不是界面层贴皮：文案的产生、传递、渲染
三处都按「码 + 参数」组织，中英两份字典在编译期互相约束。

## 一、分层与文件地图

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 语言标签 | `packages/shared/src/i18n/locale.ts` | `zh*` → `zh-CN`、`en*` → `en` 的归一；系统语言探测；语言名 |
| 翻译内核 | `packages/shared/src/i18n/core.ts` | 点号路径查表、`{param}` 插值、按 `count` 选复数形态、缺键回退链 |
| 格式化 | `packages/shared/src/i18n/format.ts` | 数字 / 百分比 / 日期 / 相对时间 / 字节 / 时长（全部走 Intl） |
| 结构化错误 | `packages/shared/src/i18n/errors.ts` | `AuroraError`（码 + 参数 + 细节）、跨 IPC 编解码、错误归一 |
| 字典 | `packages/shared/src/i18n/messages/{zh-CN,en}/*.ts` | 按命名空间分文件，**中文是源语言与唯一真值形状** |
| React 绑定 | `packages/app/src/i18n/index.tsx` | `I18nProvider`、`useT()`、`useLocale()`、`appTranslate()` |
| 语言偏好 | `packages/app/src/stores/localeStore.ts` | `system` / `zh-CN` / `en`，持久化 key `aurora-locale`（同步读写） |

语言偏好的持久化**没有**走 zustand 的 `persist` 中间件，是刻意的手写实现：
`persist` 的 hydrate 在微任务里，晚一帧就会先按默认语言渲染再重渲（可见闪烁）；
且它在存储不可访问时静默丢写。现在的实现是「模块加载时同步读一次 + 切换时同步落盘」，
与 `index.html` 首屏脚本共用同一份存储形状 `{"state":{"language":"…"},"version":1}`。

名字（我的音乐 / 音乐库）不再是字符串常量，而是文案键：见
`packages/app/src/lib/routes.ts` 的 `NAV_LABEL_KEYS`。**取值必须在渲染期**。

## 二、写界面的三条路径

```tsx
// 1. 组件内：语言切换会重渲染（首选）
import { useT, useLocale } from '@/i18n'
function Toolbar() {
  const t = useT()
  const locale = useLocale()
  return <span>{t('library.page.count', { count })} · {formatDate(new Date(), locale)}</span>
}

// 2. store / service / 事件回调（没有渲染周期）
import { appTranslate } from '@/i18n'
toast(appTranslate()('common.toast.copied'))

// 3. Electron 主进程
import { mainTranslate } from './i18n'
tray.setToolTip(mainTranslate()('nav.brand.name'))
```

## 三、硬规则

1. **不许在模块级求值文案**。`const LABEL = t('x')`、`label: t('x')`、
   模块级数组里的字符串，都会把语言冻结在模块加载那一刻。
   存**键**，在渲染期取。
2. **不许在字典里写函数**，也不许在字典值里做字符串拼接（`a + '的' + b`）。
   要拼接就写整句 + 占位符。
3. **不许在这里翻译领域数据**。歌名繁简映射、版本标记词、平台标识串
   （`LX_KNOWN_PLATFORMS` 等）参与**匹配**，翻译它们等于改匹配规则。
   它们在 `scripts/check-i18n.mjs` 的白名单里，且白名单必须写理由。
4. **复数不要手写三元表达式**。字典里写裸键（`songs`）作为 other 形态，
   需要区分的语言再补 `songs_one`，然后 `t('x.songs', { count })` 交给内核选。
5. **错误文案不许在抛出点拼中文**。底层/主进程抛
   `AuroraError('sources.error.httpStatus', { name, status })`，
   显示端 `translateError(err, t)` 渲染。渲染层已本地化的文本会被原样透出
   （保底不吞信息），但那是过渡态，不是可接受态。
6. **两种语言的占位符集合必须一致**（`{count}` 少一个都会被测试判红）。
7. **占位符不要写进例句的语法结构里**：英文语序不同，把词拆开拼必然翻车。
   写整句：`'{count} songs imported'` 而不是 `'已导入 ' + n + ' 首歌曲'`。
8. **`<html lang>` 与 `data-locale` 由 `I18nProvider` 维护**，不要另写一份。

## 四、新增文案的正确姿势

```ts
// packages/shared/src/i18n/messages/zh-CN/library.ts
const library = {
  page: { title: '我的音乐' },
  scan: {
    progress: '正在扫描 {folder}（{current}/{total}）',
    done: '扫描完成，共导入 {count} 首',
  },
}
export default library
```

```ts
// packages/shared/src/i18n/messages/en/library.ts
import type library from '../zh-CN/library'
import type { LocalizedOf } from '../schema'

const en: LocalizedOf<typeof library> = {
  page: { title: 'My Music' },
  scan: {
    progress: 'Scanning {folder} ({current}/{total})',
    done: '{count} songs imported',
  },
}
export default en
```

少一个键、拼错一个键 → `tsc` 直接报错，不需要人肉比对。

## 五、验证

```bash
node scripts/check-i18n.mjs          # 报告：还有哪些界面中文没走字典
node scripts/check-i18n.mjs --strict # 门禁：有一条即退出码 1
pnpm --filter @aurora/shared test    # 字典一致性 + 内核行为
pnpm --filter @aurora/shared build   # 必须先构建：app / desktop 依赖 dist
pnpm --filter @aurora/app exec tsc --noEmit
```

### 门禁脚本查什么

`scripts/check-i18n.mjs` 做两件事（都要绿）：

1. **界面中文扫描**：源码里的字符串字面量与 JSX 文本节点，剥离注释、跳过 `console.*` / Kotlin `Log.x(` 等日志行之后，不允许再出现中文。
   白名单有三类，且都必须写明理由：文件级（`coverMatch.ts` 这类纯数据文件）、
   值级（`DOMAIN_PLACEHOLDERS`：与 `coverMatch.PLACEHOLDER_ARTISTS` 同源的匹配占位值）、
   行级（`// i18n-exempt: 理由`，用于确有必要的个别行）。
2. **英文字典残留检查**：直接读 `packages/shared/dist/index.js`（运行时真正加载的那份数据），
   逐条检查 `en` 字典——值里出现中日韩字符即判红。键覆盖由 `tsc` 保证，
   但**值**可以是任何字符串（复制中文当占位、半成品），编译器不会说一句话，这条检查补这个洞。

### 原生侧的错误码

Android 插件（Capacitor `call.reject`）拿不到界面语言，也不该拼句子，所以按约定回**可逆码**：

```
update_error_httpStatus?status=404   →  键 mobile.update.error.httpStatus + { status: '404' }
```

规则：`mobile.` + 码里 `_` 换 `.`；`?k=v` 用 `URLSearchParams` 解出作插值参数。
`shared/src/i18n/errors.ts` 的 `parseNativeMobileCode` 负责识别，且**必须排在关键词表之前**：
码里的 `status=404` 会被 "404" 命中去猜成「文件或目录不存在」，`_canceled` 也会被 "cancel" 认成超时。

### 领域占位值为什么不在报告里

`未知艺术家 / 未知专辑 / 未知歌曲 / 合辑 / 群星` 这五个串是**匹配数据**：
`coverMatch.PLACEHOLDER_ARTISTS` 拿它们判断「歌手是否已知」，进而决定封面候选
要不要过歌手门禁。把它们翻成 `Unknown artist`，英文界面下的匹配行为就会和
中文界面不一样。`musicSource` / `lxHost` / `musicHall` / `downloadUtils` 里的
同名兜底值、desktop `ipc/scanner.ts` 的 `META_PLACEHOLDERS` 都是同一批串。

因此门禁脚本把它们列进 `DOMAIN_PLACEHOLDERS` 并跳过，同时**在启动时校验**
脚本里的这份集合与 `coverMatch.ts` 的定义逐字一致（不一致直接退出码 2）——
门禁自身也会漂移，这条自检就是防止「改了 coverMatch 忘了改脚本」变成静默放行。

## 六、常见陷阱

- **改完字典忘记重建 shared**：`@aurora/shared` 通过 `dist` 被 app / desktop 消费，
  不跑 `build` 时改动不生效，表现为「文案没变」。
- **在 zustand store 的初始 state 里放文案**：同理，模块加载期求值。
  初始值放键或 `null`，在组件里渲染。
- **`Intl.Collator`**：排序用的 locale 要跟着界面语言走（`useLocale()`），
  否则英文界面下中文歌名排序规则与中文界面不一致（那其实是正确的：
  跟随界面语言，但**不能硬编码 `zh-Hans-CN`**）。
- **时长格式不进字典**：`formatDuration` 两种语言共用同一形态（时间码），
  跟随语言会让进度条旁的数字跳动。
