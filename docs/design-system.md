## 0. 怎么用这份文档

**这是设计决策依据，不是 API 手册。** 新增界面、面板、按钮时，照这里的规则就能决定用哪种颜色、多大圆角、多宽间距、要不要玻璃与动效，且结果会和软件已有部分自动对上。

两条贯穿全稿的原则，比记住任何数值都重要：

1. **每一屏只有一个"亮点"**。层级靠灰阶和描边拉开，不靠颜色堆叠。想再加一个强调色时，先问：现有的能不能承担？（§4）
2. **材质服务于信息，不服务于装饰**。玻璃、阴影、模糊都是"这块内容浮在别的内容之上"的信号；没有浮起关系就用平铺叠色。（§3）

**怎么查**：结构性决定（底色/模糊/阴影）→ §2–§3；颜色 → §4；间距 → §5；圆角 → §6；动效 → §7；文字 → §8；交付前自查 → §9、§10；想知道为什么风格里没有某样东西 → §11。

## 1. 风格定位与气质

一句话：**克制的暗色玻璃——用发丝描边分层，用留白呼吸，只留一个情绪出口。**

| 气质 | 具体表现 | 反面（不做什么） |
| --- | --- | --- |
| 克制 | 一屏内只允许 1 个强调色，其余全是中性灰阶 | 不堆砌多色渐变、不每屏都放发光 |
| 暗色优先 | 暗色 `#0A0A0A` 是设计基准，浅色 `#F9F8F8` 是派生 | 不把浅色当默认再"反色适配" |
| 表面叠加 | 表面用**半透明白叠加**而非不透明灰（`rgba(255,255,255,.06)`） | 不用纯 `#111` 实心块冒充玻璃 |
| 发丝描边 | 恒为 `1px` 半透明描边；深浅色各自一套，见 §4 | 不用 2px+ 粗边、不用高饱和描边 |
| 胶囊形体 | 按钮/标签/切换器一律 `100px` 全圆角，语义靠填充与描边区分 | 不用直角矩形的大色块按钮 |
| 大留白 | 区块靠间距分隔，而非分割线或阴影 | 不用边框把每个区块硬切开 |
| 弱动效 | 动效只做状态反馈，幅度小、时长短 | 不做装饰性旋转/弹跳/无限呼吸 |

**层级观**：整个界面只有三种"存在感"——**页面底色**（几乎无感）、**表面**（微弱提亮）、**浮层**（明显提亮 + 模糊）。任何新元素都应落在这三层之一，**不要发明第四种**。这条是 §3 的总纲。

### 2.3.1 配色收敛为「2 色相 + 中性灰阶」

**规则**：全站只有两个色相 + DS 中性灰阶 + 一个危险语义色。新增色相前先质疑需求。

| 角色 | Token | 暗色 / 浅色 | 用途 |
| --- | --- | --- | --- |
| **主色** | `--fc-accent` / `--tw-mint` | `#00F5D4` / `#009C88` | **承担全部交互语义**（按钮、选中、focus ring、进度条） |
| **辅助色** | `--fc-accent-2` | `#4d9fd8` / `#2b7db5` | **不参与交互语义**；仅歌词高亮、装饰、频谱次色、TitleBar hover 强调 |
| **危险色** | `--tw-coral` | `255 83 103` / `226 59 82` | 仅破坏性操作（关闭窗口、删除） |

> **为什么必须收敛**：项目曾同时存在 `--chill-cyan/-blue/-mint`、`--champagne(-deep)`、`--coral`、`--fc-blue`、`--fc-warm`、`--fc-ds-blue*` 等 **9 个色族 token，而它们全部 0 引用**；与此同时 `TitleBar.tsx` 绕过 token 硬编码 `#fff1bd`（香槟色），频谱可视化又硬编码 `hsla(42,88%,64%)`（同一种香槟金）。结果是**定义了不用、用了不定义**，形成两套并行的颜色词汇，视觉上表现为"颜色不统一"。上述 token 已删除，实际在用的香槟金语义统一由 `--fc-accent-2` 承担。

**两条硬约束**（改配色时勿破坏）：

1. **禁止硬编码色值**。所有颜色走 token；浅色主题下 mint 是 `#009C88`，硬编码 `#00F5D4` 会导致浅底上过亮、失真（canvas 内的频谱曾踩此坑）。
2. **`--tw-coral` 与 `--coral` 不是两个颜色**。`--tw-coral` 是 RGB 三元组形式（供 Tailwind `<alpha-value>` 使用），全站 43 处 `text-coral`/`bg-coral`/`border-coral` 都走它；独立的十六进制 `--coral` 是冗余，已删。

**Canvas 内取色的正确做法**：canvas 无法解析 `var()`，但**支持 `color-mix()`**（已实测：`color-mix(in srgb, #4d9fd8 100%, #00F5D4)` 填充后读回像素 = `[77,159,216]`）。`useAudioVisualizer.ts` 的做法是「主题变化时 `getComputedStyle` 读一次 `--fc-accent` / `--fc-accent-2` 并缓存，绘制循环内复用」——避免每帧强制 reflow（原注释中的性能警告），同时让频谱跟随主题。

### 2.4 模糊与阴影

| Token | 值 |
| --- | --- |
| 玻璃模糊 `--ds-blur-glass` | **`12px`**（浅深色同值，全项目玻璃的唯一基准半径） |
| 卡片阴影 | `0 12px 32px rgba(0,0,0,.24), inset 0 1px 0 rgba(255,255,255,.06)`（浅色同结构、更浅） |
| 液态玻璃厚度 `--glass-liquid-edge` | 深色 `inset 0 1px 0 0 rgba(255,255,255,.34), inset 0 -1.5px 1px -1px rgba(255,255,255,.18)`；浅色 `.90 / .55` |
| 液态玻璃本体 `--glass-liquid-bg` | 深色 白 `.055→.038` 渐变 + `rgba(0,8,18,.20)`；浅色 `rgba(255,255,255,.72→.60)` |
| 液态玻璃投影 `--glass-liquid-shadow` | 深色 `0 18px 52px rgba(0,0,0,.36), 0 2px 8px rgba(0,0,0,.20)`；浅色更轻更散 |

> **暗色下"层级"主要靠内高光而非黑影**：`inset 0 1px 0 rgba(255,255,255,.08)` 这条 1px 顶边高光，比加深投影更能表达"这块浮起来了"。黑影只在浮层用（§3）。
>
> 液态玻璃把这条推到极致：厚度层的下边缘是**柔的折返光**（1.5px 偏移 + 1px 模糊），与上边缘的**锐亮线**形成不对称 —— 详见 §2.6。

### 2.5 玻璃与背景的可折射性（通透感的前提）

> **一句话：玻璃的通透感 = 背后有值得折射的东西 × 玻璃本身的透光率。模糊半径只是次要变量。**

这条是本项目一次视觉返工后补充的结论。当时的"玻璃不玻璃"表现为整体死灰，排查发现：

- `backdrop-filter: blur()` **一直正常生效**，但背景是 `rgb(10,10,10)` 的近纯黑；
- **模糊作用在近纯黑上，数学上等于什么都没做** —— GPU 代价全额支付，视觉收益为零；
- 玻璃底是 `rgba(18,18,18,.72)`（72% 不透明的近黑），把背景**盖住**而不是**透出**。

因此调整玻璃前，**先确认背景有内容可折射**，否则调模糊半径是无效劳动。

| 要素 | 要求 | 本项目取值 |
| --- | --- | --- |
| **背景色场** | 必须有**高不透明度、有色相**的色场；纯黑底上玻璃必然"假" | `--ambient-*` 三色斑，alpha `.34~.50`，叠在 `--ambient-base` 有色底上 |
| **色场实现方式** | 用 `filter: blur()` 作用于**元素自身**（合成层），不要用 `backdrop-filter`；且**色斑必须分层独立成元素** | `.ambient-blob--primary/secondary/glow` 三个独立元素，各带 `filter: blur(80~110px)` |
| **玻璃底** | 低 alpha"压暗场/提亮场"，**不要用高不透明实心色** | 暗色 `rgba(0,6,14,.17)` + 白 `.055` 提亮；浅色 `rgba(255,255,255,.40)` |
| **玻璃模糊** | 足够长才能把背景柔化成"色雾"而非可辨形状 | `18~28px`（`.glass-subtle` → `.glass-strong`） |
| **玻璃滤镜附加项** | `saturate` 让透出的色场更鲜活；`brightness` 微提避免压暗发灰 | `saturate(1.4~1.6) brightness(1.04~1.06)` |
| **封面取色驱动** | 取色需**提饱和 + 设亮度下限**，否则灰封面会让背景重回死灰 | `useThemeColor.ts` 的 `toFieldColor()` |

**压暗层的 alpha 是"通透度"主旋钮**（不是模糊半径）。实测标定：受光场色 L≈0.0576 上，冷黑 `.26` 合成后 L≈0.0474（ΔL=-0.010）。

> **浮层不应比普通面板更不透**。改造前 `--glass-floating-bg` / `--glass-popover-bg` 用 `.48`/`.50`，是 `regular`（`.26`）的近两倍，合成后 L≈0.027（ΔL=-0.030）——**"浮起来"的层反而最不透**，与层级语义相反。现统一收敛为 `.24`/`.26`，层级改由**内高光强度 + 投影**表达（`--glass-edge-highlight` `.16`→`.20`，`--glass-floating-shadow` 的 inset 高光 `.16`→`.20`）。
>
> 浮层仍比普通面板多压约 `.07`（`.24` vs `.17`），因为浮层背后可能是任意内容（歌词、封面），需要略强的可读性兜底。

**次要文字的最低 alpha = `/65`**。色场提亮后，`text-white/40`~`/50` 的次要文字（侧栏分组标题、版本号、页面副标题）实测对比度跌到 2.6~3.9，低于 WCAG AA 的 4.5。统一提到 `/65` 后实测：侧栏导航项 5.26~14.02、分组标题 4.59~5.21、版本号 5.11~5.23，两套主题全部达标。

**三个易踩的坑**（都已在代码中处理，改动时勿破坏）：

1. **自定义属性默认不可插值**。改 `--ambient-*` 会瞬间跳变而非平滑过渡；要平滑必须用 `@property` 注册成 `<color>`（本项目已注册，`transition: --ambient-from … 0.9s` 才生效）。
2. **`::before` 是静态色底，任何降级规则都不能隐藏它**。只可隐藏带 `filter` 的色斑元素。把静态底一起藏掉，窗口缩放/resizing 期间背景会闪黑。
3. **色斑不能塞进同一个元素的 `background` 列表**。多段 `radial-gradient` 写在同一元素里会先叠加成一张图、再整体模糊，各色相互相中和成一片灰雾；必须**分开成独立元素**，每层各自保持色相与边缘，玻璃才折射得出「一条条光带」而不是「一团糊」。这是"分层"与"分元素"的区别——前者只是叠色，后者才有折射细节。

**亮度标定**（决定"通透"还是"发灰"）：参考站色场亮度落在 **L≈0.0496~0.0687**。低于此区间玻璃透不出光（看起来是暗色板），高于则色场喧宾夺主、文字对比度崩。本项目实测标定为 L≈0.039~0.057（受光区 0.053~0.057），深色 `--ambient-base: #0a1524`。

### 2.6 液态玻璃材质（`glass-liquid` / 厚度层）

> **一句话：液态玻璃的"厚度"来自边缘光带的「上锐下柔」，不是来自模糊半径，也不是来自转角亮斑。**

参考图（Apple 风格的液态玻璃）最抓眼的特征是玻璃边缘把背后画面**推挤变形**（真实几何折射）。本项目尝试复刻，结论是**纯 CSS 做不到**，已放弃并改用可靠手段还原"液态"观感。以下全部是实测结论，改动前务必先读。

#### 为什么不做几何折射（避免后人重走弯路）

用 `backdrop-filter: url(#filter)` + `feDisplacementMap` 位移场实现折射，实测在 Chrome 下**不可行**：backdrop-filter 的滤镜链**拿不到任何外部图像**。

| 位移场来源 | 结果 |
| --- | --- |
| `feImage href="data:image/svg+xml,..."` | ❌ 位移场为空，滤镜无任何效果 |
| `feImage href="#内联 <image>"`（其 href 为 data:） | ❌ 同样无效果 |
| `feImage href="blob:..."` | ❌ 同样无效果 |
| `feTurbulence`（滤镜图元自生成，不依赖图像） | ✅ **有效** |

**判定方法**（可复现）：把「白线网格」放在玻璃背后，若位移生效网格会弯曲。
前三种情况下**网格笔直不动**——注意这不是"参数调小了"：实测改 `band`/`strength`/`scale`
对渲染结果**字节级无差异**（MD5 相同），说明位移场根本没被读到。

**为什么不用 `feTurbulence` 顶替**：玻璃的位移场是**平滑且沿边缘单调变化**的（菲涅尔透镜式），
而湍流是随机噪声，位移后呈现大理石/水波纹，与"通透、干净"的设计语汇冲突。

> 若将来确实需要真折射，唯一可行路径是 **Canvas 实时采样背景自行渲染**，而不是 CSS 滤镜。

#### 液态玻璃的三个可落地要素

| 要素 | 做法 | 取值 |
| --- | --- | --- |
| **厚度**（最关键） | 顶部细锐亮线 + 底部柔和折返光 | `--glass-liquid-edge`：`inset 0 1px 0 0 rgba(255,255,255,.34)` + `inset 0 -1.5px 1px -1px rgba(255,255,255,.18)` |
| **内部色染** | 本体足够透明，让背后色场透上来；**不额外上色** | `--glass-liquid-bg`：白 `.055→.038` 渐变 + `rgba(0,8,18,.20)` |
| **形态** | 大圆角是液态感的形状语言，直角会退化成"卡片" | 沿用既有圆角语义（§6） |

**「上锐下柔」是厚度感的核心**：顶部用 1px 零模糊（掠射反射是锐的），底部用更大模糊半径 + 负偏移
（光穿透玻璃后在底缘折回，边缘是柔的）。这个不对称正是"一块有厚度的材料"与"一条描边"的分界。

**alpha 经并排实测校准**（`.glass-liquid` 的 `::before`）：

| 上/下 alpha | 观感 |
| --- | --- |
| `.20 / .08` | 太平，无厚度感 |
| **`.34 / .18`** | **最佳点：有厚度但不描边** |
| `.44 / .22` | 退化成"描边"，玻璃感消失 |

#### 刻意不做「转角聚焦亮斑」

参考图的玻璃四角有明显的亮斑（圆角处两方向边缘光叠加）。本项目**实测否决**了这个做法：
在**暗背景**下四角亮斑会变成"四角发白的污渍"，因为白斑落在暗底上没有可依托的亮背景，只会显脏。
参考图的转角亮斑之所以成立，是因为它背后是**明亮的彩色实景照片**。
> 若将来背景色场显著提亮（接近参考站的 L≈0.05~0.07 上限），可再评估加回。

#### 两条实现硬约束（改动时勿破坏）

1. **厚度层必须用 `::before` 画，不能写进 `box-shadow`**。
   侧栏/标题栏的 class 带 Tailwind 的 `shadow-none`（它们紧贴窗口边缘，外投影会被裁掉显脏，故有意去掉），
   而 `shadow-none` 会把 `box-shadow` **整个覆盖掉**。实测：厚度写在 `box-shadow` 上时，侧栏的
   `box-shadow` 被静默清零成三个透明占位值，"所有面板统一厚度"的约定在最重要的侧栏上失效。
   用伪元素画则与 `box-shadow` 完全解耦。
2. **降级开关必须同时隐藏厚度层**。`.glass-flat` 下要 `content: none` 掉
   `.glass-liquid / .glass-regular / .glass-strong / .glass-subtle` 的 `::before`，
   否则降级态会在整块不透明面板上留一圈无意义的白描边。
   ⚠️ 注意**不要波及 `.ambient-backdrop::before`** —— 那是背景静态底，隐藏会导致背景闪黑（见 §2.5 坑 2）。

**降级行为**（`.resizing` / `.glass-perf-lite`）：只关 `backdrop-filter`，**保留厚度层**。
厚度是廉价的 `box-shadow`，关掉没有性能收益，保留能让动画期间的视觉不突变。

#### 材质选用

| 类 | 用于 | 说明 |
| --- | --- | --- |
| `glass-liquid` | 浮层：下拉菜单、右键菜单、弹窗、搜索浮层、播放队列 | 材质升级版：更透 + 完整厚度层 |
| `glass-regular` / `glass-strong` / `glass-subtle` | 常驻面板：侧栏、标题栏、右侧 Now Playing | 各自透明度语义不变，统一挂载厚度层 |
| `glass-saved-panel` | 播放条 | 厚度写在自己的 `--saved-panel-glass-shadow` 里（不走伪元素） |

> **`glass-liquid` 与 `glass-floating` 不要叠加使用**。两者都声明 `background`/`border`/`backdrop-filter`，
> 叠加会让同一属性由两个类重复声明、生效结果依赖 CSS 顺序。`glass-liquid` 是 `glass-floating` 的替代而非补充。
> 保留 `glass-floating` 供**小面积信息层**（Toast、重复歌曲提示）使用 —— 液态玻璃的厚度感在那种尺寸上不明显，
> 且它们更需要强可读性。

## 3. 层级与纵深：什么时候用玻璃、叠色、阴影

这是全稿最常用的一节。**先判断元素的浮起关系，再选材质。**

### 3.1 决策树

```
这个元素是否浮在「别的内容」之上（滚动时会盖住下面）？
├─ 是 → 它是浮层
│   ├─ 是临时性、需要"焦点感"的（弹窗、下拉、右键菜单、模态）
│   │     → 玻璃：backdrop-blur(12px) + 发丝边 + 浮层阴影 + 圆角 panel/card
│   └─ 是常驻的（顶栏、底部播放条）
│         → 玻璃，但**默认可以透明**，只在"内容滚到它下面"时才淡入玻璃（§3.4）
└─ 否 → 它和周围内容同一平面
    ├─ 需要一点"我是独立一块"的感觉 → 表面叠色：rgba(255,255,255,.06) + 发丝边
    └─ 只是行/块的轻微区分 → 表面叠色更弱档：.04 / .02，通常连描边都不要
```

### 3.2 三种材质的适用条件

| 材质 | 什么时候用（**充分条件**） | 关键数值 | 什么时候**不要**用 |
| --- | --- | --- | --- |
| **玻璃**<br>`backdrop-filter` | ① 元素会盖住**有内容的背景**（列表、封面、歌词），且 ② 这块内容会**移动**（滚动/拖拽），用户需要感知"底下还有东西" | `blur(12px)` + 发丝边 `1px` + 半透明底 | 背景是纯色页面底时——没有东西可折射，玻璃只是白付性能；背景不滚动的大面板优先钝感实色 |
| **表面叠色**<br>`rgba(255,255,255,.06)` | 元素处于内容流内部，需要"独立成块"但**没有浮起关系**：卡片、列表项、代码块、输入框 | `.06`（可交互块）/ `.04`（次级）/ `.02`（最弱底色） | 不要为了"好看"给纯文本段落加背景块 |
| **阴影** | 仅在**浮层**上使用，且必须是柔和、单层为主的大范围投影 | 项目卡片用 `0 12px 32px rgba(0,0,0,.24)`；暗色下配 `inset 0 1px 0 rgba(255,255,255,.08)` 内高光 | **不要给内容流里的卡片加重阴影**——那是在用阴影模拟"浮起"，但卡片并不浮起，视觉会脏 |

### 3.3 表面叠色为什么用半透明白

`rgba(255,255,255,.06)` 叠在**任何**底色上都成立：页面底、封面取色光晕、图片上，结果都自然提亮一层。而写死的 `#1a1a1a` 一旦落到别的底色上就会露出"色块边界"。**所以新增表面一律用半透明白/黑，不要用不透明灰。**（浅色主题下方向相反：用 `rgba(0,0,0,.03)` 这类半透明黑。）

### 3.4 常驻玻璃的"懒出现"规则

顶栏这类**常驻**元素有一个专门的模式：**静止时完全透明，只有在它盖住内容时玻璃才淡入**。

- 顶栏初始 `background: transparent`，滚动到阈值后加 `.is-scrolled`，玻璃层 `opacity 0 → 1`（`0.4s ease-in-out`）。
- 好处：首屏干净、无"贴片感"；滚动后自动获得可读性。
- 底部播放条同理：**内容没滚到它后面时不要显玻璃**。

### 3.5 性能红线（务必遵守）

`backdrop-filter` 是**逐帧重采样**，代价远高于普通背景色。

- ❌ **禁止在大面积、且会随滚动移动的元素上用 `backdrop-filter`**。项目里 `.card-solid` 就是为此存在的：与 `.card-utility` 观感一致，但**不带** blur，用于长列表卡片——因为背景渐变本身已近不透明（`.66/.76`），blur 折射收益极小，却会造成详情页滚动卡顿。
- ❌ **禁止嵌套多层 backdrop-filter**（玻璃里再放玻璃），代价叠加且视觉发灰。
- ✅ 玻璃只用在小面积浮层（下拉、弹窗、播放条、顶栏）上。
- ✅ 需要"卡顿安全模式"时，项目已有 `.glass-perf-lite` / `.resizing` 降级规则在兜底，新增玻璃元素请沿用同一降级思路。
- ⚠️ **注意区分 `backdrop-filter` 与 `filter`**：背景色场用 `filter: blur()`（作用于元素自身，走合成层，一次模糊可长期复用），**不要**误用 `backdrop-filter`（逐帧重采样，且需要背后有东西才有效果）。二者代价差一个量级，§2.5 的色场正是因此选用 `filter`。
- ⚠️ **新增/改名玻璃类后，必须同步更新三处降级规则的类名清单**：`.glass-flat`、`.resizing`、`.glass-perf-lite`。漏一个就会出现"降级开关没关掉这块玻璃"的性能隐患。改完用 `getComputedStyle` 断言三处均为 **8/8 覆盖**（当前玻璃类总数 8）。
- ⚠️ **降级开关必须写 `!important`**：`html.control-glass-svg-ok .glass-saved-panel`（特异性 0,2,1）高于 `.glass-flat .glass-saved-panel`（0,2,0），不加 `!important` 时总开关会静默失效，恰好在"性能降级"模式下保留最贵的 `blur(24px)`。此坑已实际发生过一次。
- ⚠️ **色斑降级要保底一层**：`.glass-flat`/`.resizing` 只该藏掉**带 `filter: blur()` 的**色斑，其中 `.ambient-blob--depth` 是纯 `linear-gradient`（无 filter，代价近似为零），必须保留，否则降级态背景会退回一块死黑。

## 4. 颜色使用规则

### 4.1 主色（mint）只做三件事

**`--fc-accent`：暗色 `#00F5D4` / 浅色 `#009C88`。**

| ✅ 用 mint | ❌ 不用 mint |
| --- | --- |
| 主行动按钮的**填充**（"播放全部""保存"） | 整块背景/整页底色 |
| 当前选中项、激活态、正在播放的标识 | 正文文字（浅色下对比度不足） |
| 数据可视化里的**唯一**强调系列 | 多个不同系列（那样应改用灰阶深浅区分） |
| 焦点环 `/焦点描边` | 大面积的 hover 底色 |
| 播放进度条的已播放段 | 装饰性边框、分隔线 |

**判断准则**：如果一个界面里 mint 出现了 3 处以上、或者占据的**面积**超过一个小按钮，那就是过度使用——回到灰阶去表达层级。

### 4.2 灰阶承担其余一切

暗色下：`#0A0A0A`（底）→ 白 `.02/.04/.06/.12`（表面递进）→ `#FFFFFF / #D6D6D6 / #8C8C8C`（文字三级）→ 白 `.06/.08/.24`（描边递进）。

**层级顺序不要跳档**：文字三级（主/次/描述）要连续使用，不要出现"主文字 + 描述文字"却跳过次级的情况。同理表面 `1→2→3` 应按嵌套深度递增，不要同层用两个不同档。

### 4.3 DS 品牌蓝的定位

`--fc-ds-blue`（浅 `#4d6bfe` / 深 `#6799fe`）在本项目中是**保留的辅助色，默认零消费**。

- ✅ 可用于：图表里的第二个数据系列、品牌露出位（如"由 Aura 提供"这类无关交互的来源说明）。
- ⚠️ **浅色下 `#4d6bfe` on `#F9F8F8` 仅 4.08:1，未达 4.5:1**。若要把它当正文或链接色，必须先用更深的值。
- ❌ 不要把 DS 蓝和 mint 放进同一个界面——两个强调色同屏，视觉会立刻失焦。

### 4.4 浅色主题的对比度红线

浅色主题不是"暗色反个色"，它有自己的约束：

| 组合 | 实测对比度 | 结论 |
| --- | --- | --- |
| `#1E232C` on `#F9F8F8`（主文字） | ≈14.9:1 | ✅ |
| `#3C424C` / `#5C636E`（次/描述） | ≈9.5 / 5.7:1 | ✅ |
| mint `#009C88` on `#F9F8F8`（作**文字**） | ≈3.2:1 | ❌ 不达 4.5:1，**不要用作正文色** |
| mint `#009C88` 作**填充**、上面压白字 | ≈3.4:1 | ❌ 不要；项目里 mint 按钮的前景恒为深墨 `#030608`（5.9:1 ✅） |
| `rgba(255,255,255,.3)` 类极浅文字（浅色下已翻转为深墨低透明） | ≈3.5:1 | ⚠️ 既有状态，仅可用于装饰性微标 |

**规律**：浅色主题下所有"亮色强调"都会掉对比度，因此 **mint 在浅色下只做填充，不做文字**；文字层的强调改用"更深的中性色 + 加粗/加大"来表达。

**新增颜色前的自检**：任何新文字色都要 ≥4.5:1（大字号可用 ≥3:1），任何新交互色都要在**两套主题下**都达标。

## 5. 间距节奏

阶梯只有一句话：**4 / 8 / 12 / 16 / 24 / 32 / 40 / 56 / 80 / 120 / 160 / 200 / 240**。

### 5.1 按"作用距离"选档

| 你在调什么距离 | 用哪档 | 常见取值 |
| --- | --- | --- |
| **元素内部**：图标与文字、图标与按钮边、标签内边距 | 小档 | `4 / 8 / 12` |
| **同组元素之间**：一行里的两个按钮、列表项之间、表单行之间 | 中档 | `12 / 16 / 24` |
| **组与组之间**：卡片与卡片、标题与它下面的内容块 | 中大档 | `24 / 32 / 40` |
| **区块与区块之间**：页面的主要段落、模块分节 | 大档 | `56 / 80` |
| **页面级留白**：首屏上下、章节之间的大呼吸 | 特大档 | `120 / 160 / 200 / 240` |

### 5.2 三条可执行准则

1. **相邻层级至少差一档**。内边距 12、组间距 16、区块间距 32，这样"谁属于谁"一眼可辨。若内边距和组间距同为 16，内容就会糊成一片。
2. **容器内边距 ≥ 组间距**。一个 `p-16px` 的卡片里，元素间距不要超过 16px，否则卡片会显得"内容是挤进来的"。
3. **间距优先于分割线**。想分开两个区块时，先把间距加大到 `56/80`；只有当间距大到你无法接受时才用一条 `rgba(255,255,255,.06)` 的分割线。**分割线是妥协，不是首选。**

### 5.3 典型场景对照

| 场景 | 建议 |
| --- | --- |
| 卡片内：标题 → 说明文字 | `8` |
| 卡片内：文本块 → 底部按钮组 | `24` |
| 列表项内：封面缩略图(48px) → 标题/副标题 | `12` |
| 列表项本身的高度/间距（歌曲行） | 行高 `56` 左右，行间不加间距 |
| 页面左右留白（桌面） | 内容区居中，最大宽约 1140/1280，两侧留白随断点从 48 增至 160 |
| 页面顶部到第一个标题 | `56 / 80` |
| 弹层内边距 | `16 / 24` |

### 5.4 容器宽度

内容不要铺满屏幕。**大屏靠留白而非拉宽内容维持可读性**：正文最大宽度控制在约 1140px（超宽屏 1280px），长文段落再窄一档（约 650–700px）。

## 6. 圆角语义

圆角不是"大小随意"，它编码了**元素的形状类别**：

| 圆角 | 对应元素类别 | 为什么 |
| --- | --- | --- |
| `100px`（pill） | 按钮、标签、切换器、搜索框、进度条端点 | 全圆角 = "这是一个可点的动作/开关"，形状本身就在提示可交互 |
| `24px`（card） | 内容卡片、专辑/封面大卡 | 卡片的面积大，圆角需同比放大才不显尖；24px 让大色块看起来柔和 |
| `16px`（panel） | 面板、下拉、列表容器、弹层 | 中等面积容器，比卡片收一档，避免"每条列表都是圆角大卡" |
| `10px`（media / input） | 封面缩略图、图标按钮、输入框、分段控件 | 小面积元素的圆角要有"克制感"；再小就接近直角，再大就接近胶囊 |
| `8px`（sm） | 徽标、小图标容器、极小的内嵌元素 | 最小可视圆角，保留一点柔性 |

### 分级逻辑

- **面积越大，圆角越大**，但**增长率递减**：`24 → 16 → 10 → 8`。这样整套 UI 在大卡与小徽标上呈现同一种"柔"的调性，而不是小元素照抄 24px 变成药丸。
- **同一层级保持一致**：一屏内所有卡片用同一档，不要这张 24px 那张 16px。需要区分优先级时用**表面深浅**和**描边**，不要用圆角。
- **嵌套时内层小一档**：外层 16px 面板里嵌的小块用 10px 或 8px，避免内外圆角同心错位。

### 注意

- 项目里既有的 `--r-pill` 现在也是 `100px`（原为 50px，已刻意胶囊化）。
- **任意值硬编码圆角是历史遗留**，新增代码请直接使用上表的 token / `rounded-ds-*` 工具类，不要再写 `rounded-[10px]` 这类字面量。

## 7. 动效规则

### 7.1 时长：短、分级、不拖沓

| 时长 | 用途 | 例子 |
| --- | --- | --- |
| `0.1s` | 纯透明度变化 | 按钮 hover 底色的淡入 |
| `0.16–0.18s` | **交互反馈的默认值** | 按钮 hover 的位移/缩放/颜色（项目里 `.18s` 出现 27 处，是最常用的档位） |
| `0.2s` | 中等状态的切换 | 描边色、背景色过渡、面板显隐 |
| `0.22–0.28s` | 带位移的过渡 | 卡片 hover 上浮 `-2px` |
| `0.3s` | 淡入淡出类 | CTA 描边显形、遮罩 |
| `0.36s` | **径向扩散** | 按钮 `::after` 从中心 `scale(0)→scale(1)` |
| `0.4s` | 大范围的显隐 | 顶栏玻璃淡入 |
| `0.6–0.8s` | **仅首屏入场**，点状使用 | hero 元素错位入场（`0.8s` + `backwards`） |

**判断准则**：动的是"颜色/透明度"→ 用 `0.18s`；动的是"位移/尺寸"→ 用 `0.22–0.28s`；动的是"整块出现/消失"→ 用 `0.3–0.4s`。**任何超过 `0.4s` 的常规交互过渡都算慢**，只有首屏入场可以到 `0.8s`。

### 7.2 缓动

- 默认交互：`--ease-apple` = `cubic-bezier(.25,.1,.25,1)`（对称、稳重）。
- 需要"快出慢收"的位移（卡片上浮、面板展开）：`--ease-mineradio` = `cubic-bezier(.16,1,.3,1)`。
- 柔和版：`--ease-mineradio-soft` = `cubic-bezier(.22,1,.36,1)`。
- **不要用 `linear`**，除非是持续恒速的旋转（如 CTA 的 conic 描边 `6s linear infinite`）；`ease-in-out` 只用于对称的淡入淡出。

### 7.3 允许的动效

- ✅ **状态反馈**：hover 时背景/描边变化、上浮 `-1px ~ -2px`、按下 `scale(.96)`。
- ✅ **径向扩散**：按钮 hover 时从中心扩散一个 `150%` 宽的圆（`0.36s ease-out`），是这套风格里**唯一允许的"大面积动效"**。
- ✅ **玻璃淡入**：顶栏/浮层随滚动或开合淡入，`0.3–0.4s`。
- ✅ **入场**：首屏元素 `translateY(20px) + blur → 0`，`0.8s ease-out backwards`，可错位（每级延迟 `0.1s` 左右）。
- ✅ **常驻缓慢装饰**：CTA 卡片的 conic 旋转描边（`6s linear infinite`，且默认 `opacity:0`，hover 才显形）——**幅度小、不抢视线**才允许。

### 7.4 禁止的动效

- ❌ **大面积逐帧模糊**：不要在会滚动的大区块上同时做 `backdrop-filter` + `transform` 动画（每帧重采样 → 掉帧）。用透明度或位移替代。
- ❌ **无限循环的呼吸/脉动/旋转装饰**（除上一条那个 6s 描边）。它们抢注意力且耗电。
- ❌ **多属性同时弹跳**（`scale` + `rotate` + `translate` 一起）。一次只动 1–2 个属性。
- ❌ **超过 `0.4s` 的交互反馈**，会让界面显得"黏"。
- ❌ **列表项 hover 时整块位移**：鼠标扫过会让整个列表跳动。需要 hover 效果时，只改背景/描边（项目里 `.card-list` 就是"同材质但不上浮"的解法）。

### 7.5 必须尊重 `prefers-reduced-motion`

**所有动效都要有降级路径**，这不是可选项：

- 入场动画 → 直接显示终态（`animation: none` + 归零 transform/filter）。
- 径向扩散 → 保留 `opacity` 过渡（`0.1s`），去掉 `transform` 缩放。
- 旋转/位移 → 关掉 `animation` 与 `transform`，只留颜色过渡。
- 参考实现见 [ds-components.reference.css](../packages/app/src/styles/ds-components.reference.css) 末尾的 `@media (prefers-reduced-motion: reduce)` 块——新增动效请照此补降级规则。

## 8. 排版层级

**本项目沿用软件自身的字体**（中文优先栈），不引入风格来源的品牌字体——原因见 §11。

### 8.1 层级表

| 层级 | 字号 | 字重 | 行高 | 字距 | 什么时候用 |
| --- | --- | --- | --- | --- | --- |
| display | 40 → 64px (md) | 500 | 140% | `-0.02em` | 全屏播放页/品牌首屏的唯一主标题 |
| hero | 36 → 46px (md) | 500 | 150% | `-0.02em` | 页面级主标题，一屏一个 |
| heading1 | 28 → 36px (md) | 500 | 150% | `-0.02em` | 页面内主分节标题 |
| heading2 | 22 → 28px (md) | 500 | 150% | `-0.02em` | 二级分节 |
| heading3 | 18 → 20px (md) | 500 | 150% | `-0.02em` | 三级分节 |
| subtitle | 20px | 500 | 150% | `-0.01em` | 卡片/模块的引导句 |
| title | 18px | 500 | 150% | `-0.01em` | 卡片标题、列表主标题、歌名 |
| body | 16px | 400 | 160% | — | 正文 |
| caption | 14px | 400 | 150% | — | 说明文字、副标题、元信息 |
| xs | 13px | 400 | 150% | — | 微标、时间戳、次要元信息 |

### 8.2 使用准则

1. **明确层级用字重区分**：`title`(500) / `body`(400) 对比。若标题和正文都是 400，界面会失去结构感。
2. **不要跳级**：`body 16px` 直接跳到 `hero 46px` 做正文标题会很突兀。相邻级差 `2–8px`，保证层次连续。
3. **一屏一个展示字**：`display` / `hero` **每屏最多一个**。都用等于都不用。
4. **字号与字距联动**：只有 `display/hero/heading1-3` 用负字距 `-0.02em`（大字距过宽会散）；正文一律不加字距。
5. **行高与信息密度反相关**：正文 `160%` 便于阅读；标题 `140–150%` 更紧凑；列表行靠**行高**而非 margin 撑开（如歌曲行约 56px）。

### 8.3 中文的字重克制（重要）

**中文笔画密度远高于拉丁字母，同一字重在中文下视觉会明显更粗、更糊。** 因此：

- **中文标题在 `:lang(zh)` 下字重从 500 降到 400**。项目已在 `display / hero / heading1-3 / subtitle / title` 全层级落实，且同时覆盖 `:lang(zh)` 本身与其祖先两种写法。
- **中英混排时以中文侧为准**：若一段文字里中文占主体，即使含拉丁词也按中文字重走。
- **不要用 `font-weight: 700` 以上的粗体做中文标题**——不是不能粗，而是"细一档"几乎总比"糊一团"好看。需要强调时优先**加字号**或**改颜色层级**。
- 数字与代码建议用等宽字体（`font-mono`），让时长/编号/码值对齐。

## 10. Do / Don't

### Do

- ✅ **要强调一个操作** → 用 mint **实心胶囊**（圆角 100px、深墨前景字），而不是加大字体或加粗描边。
- ✅ **要区分两条信息的主次** → 用**文字层级**（主 `#FFF` / 次 `#D6D6D6` / 描述 `#8C8C8C`），而不是给次要信息加背景块。
- ✅ **要让一块内容"独立成块"** → 表面叠色 `rgba(255,255,255,.06)` + `1px` 发丝边 + `16px` 圆角。
- ✅ **要让内容"浮起来"** → 玻璃（`blur(12px)`）+ 柔和阴影 + `1px` 顶边内高光（暗色下尤其重要，§2.4）。
- ✅ **要划分区块** → 先把间距加到 `56/80`；真不够再用 `1px` 分割线。
- ✅ **要表现"当前选中"** → mint 描边 + 极轻的 mint 底（`rgba(0,245,212,.08)` 量级），而不是整条 mint 色块。
- ✅ **要保持一屏层次连续** → 同类元素圆角一致、间距走同一档阶梯，不要"这张卡这样、那张卡那样"。
- ✅ **要区分多个并列数据系列** → 用灰阶的**深浅**（白 `.8/.6/.4`），只有其中一个用 mint 做强调。
- ✅ **要给长列表卡片做背景** → 用无 blur 的 `.card-solid` 类材质，背景已近不透明，省下逐帧重采样（§3.5）。

### Don't

- ❌ **不要用 mint 给整块背景上色**，也不要在一屏里放第二个强调色。
- ❌ **不要在浅色主题下用 mint（或任何亮色）做正文文字**——对比度必然不达标（§4.4）。
- ❌ **不要给内容流里的卡片加大阴影**：阴影 = "浮起"，卡片没浮起，加了只会显脏。
- ❌ **不要在大面积滚动区块上用 `backdrop-filter`**，更不要嵌套多层玻璃。
- ❌ **不要试图用 CSS 滤镜做几何折射**：`feImage` 在 backdrop-filter 里读不到图像，唯一能跑的是 `feTurbulence`，而它是噪声不是玻璃（§2.6）。
- ❌ **不要把液态玻璃的厚度写进 `box-shadow`**：会被 Tailwind 的 `shadow-none` 静默覆盖，必须用 `::before`（§2.6）。
- ❌ **不要给液态玻璃加"转角聚焦亮斑"**：暗背景下会变成四角发白的污渍（§2.6）。
- ❌ **不要叠加 `glass-liquid` 与 `glass-floating`**：两者声明同一批属性，生效结果依赖 CSS 顺序（§2.6）。
- ❌ **不要用 2px+ 的粗边**，也不要高饱和描边——发丝感一破，整套风格就散了。
- ❌ **不要在暗色下用 `#111` 这类不透明灰当表面**：用半透明白叠加，才能适配任何底色。
- ❌ **不要在 hover 时让整个列表/大卡位移**——只改背景与描边色。
- ❌ **不要做无限循环的呼吸/旋转装饰**，除非它幅度极小且默认不可见（如 CTA 描边）。
- ❌ **不要做超过 `0.4s` 的交互过渡**，也不要省略 `prefers-reduced-motion` 降级。
- ❌ **不要靠圆角区分优先级**（同层用同档圆角，靠表面深浅区分）。
- ❌ **不要跳级用字号**，也不要用 `700` 以上字重做中文标题。
- ❌ **不要两套组件词汇并存**：本项目用 `.btn-*` / `.card-*` / `.glass-*` 这类语义类，不要新写 `.ds-btn-*` 这类类名（§12）。

## 11. 本项目不采纳的项

风格来源站点上有一些元素，本项目**有意不使用**。这不是遗漏，是设计决策：

### 11.1 品牌字体（不采纳）

**风格来源使用的 Host Grotesk / DM Sans / Fragment Mono 均为商业授权字体，直接引用存在版权风险，因此本项目不引入，字体沿用软件自身既有的中文优先字体栈；本设计稿也不包含字体部分。**

这条决策的依据：

- 字体授权是**法律风险**，不是审美取舍——设计稿不应把一个需要付费授权才能合法使用的资源写成规范。
- 项目主体是中文界面，这些拉丁字体**不含中文字形**，照搬后中文会回退到系统默认字体，反而造成中英混排割裂。
- 因此字体**不参与风格换肤**：新增界面直接用项目既有字体，排版层级靠**字号 / 字重 / 行高 / 字距**表达（§8），这套层级本身就足以承载风格。

> 技术侧同步：`ds-tokens.css` 中的 `--ds-font-*` 变量仅作为"上游事实"保留供查阅，**项目中无任何地方消费它们**。

### 11.2 DS 组件类库（不采纳）

风格来源的 `.ds-btn-*` / `.ds-container` / `.ds-text-*` 等组件类**不进入生产构建**：

- 本项目的组件语义类（`.btn-primary` / `.card-utility` / `.glass-*` 等）已经承担了组件层职责，再叠一层 `.ds-` 组件类会产生**两套并行的组件词汇**，后续维护者不知道该改哪一套。
- 原文件已更名为 `ds-components.reference.css`，并**移出生产构建**（`globals.css` 的 `@import` 已移除它，仅保留 `ds-tokens.css`）。
- 它的价值转为**参考实现**：想确认某个效果的原始做法时去读它，或打开 `ds-showcase.html` 看视觉对照。**(本项目不使用其中任何 `.ds-` 类。)**

### 11.3 其它未采纳的效果

| 项 | 原因 |
| --- | --- |
| `.ds-font-harness`（`Edit Undo` 像素风字标） | 同为第三方字体 + 纯装饰性，与产品气质无关 |
| 浅色取向的网格背景默认值 | 原值 `rgba(0,0,0,.025)` 在暗色下不可见，需换白色低透明；且网格是营销页手法，播放器界面用不上 |
| Montserrat 展示字体 | 与 §11.1 同因（外部字体依赖），排版层级改用字号/字重表达 |

## 13. 与 Mineradio 既有主题的关系

本项目的现状是：**结构、材质、灰阶、圆角、间距、动效取自 DeepSeek Harness；主交互色保留项目自己的 mint。** 这不是"两套主题并存"，而是**一套视觉体系 + 一个品牌色**。

| 维度 | 说明 |
| --- | --- |
| 风格来源 | 层级/材质/发丝边/胶囊形体/大留白/弱动效 |
| 主色 | Mineradio mint `#00F5D4`（浅 `#009C88`），承担**全部交互语义** |
| 辅助色 | DS 蓝 `--fc-ds-blue*`，默认零消费（§4.3） |
| 变量命名 | `--fc-*` 为项目主题变量，`--ds-*` 为设计 token，二者作用域隔离、互不覆盖 |
| 字体 | 项目原有中文优先栈（§11.1） |

**取舍原则**：

1. **一个界面一个强调色**：mint 在的地方就不要放 DS 蓝。
2. **不反向覆盖**：不要用 `--ds-*` 去改 `--fc-*` 的值，它们是"参考"与"落地"的关系。
3. **风格统一优先于局部个性**：播放器的封面取色光晕、玻璃 SVG 滤镜是项目的特色机制，**保留**；但它们的模糊半径、圆角、阴影层数已经收敛到本稿的量级（`blur 12px`、圆角对齐 DS 阶梯、阴影层数精简到 1–2 层），新增氛围效果请沿用同一量级。
