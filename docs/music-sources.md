# 音源协议

> 应用不内置**可播放**的音源：在线搜索、歌词匹配与歌单解析都依赖用户自行配置的 HTTP 接口，
> 或按洛雪格式自备的音源脚本（设置 → 在线源）。**一条音源同时提供这几种能力**。
> 唯一例外是内置的「聚合搜索」插件 —— 它只补**搜索**这一段（见下文「内置聚合搜索」），
> 播放地址仍由你自己的音源或脚本给出。

## 多个音源同时配置时谁优先

结果顺序就是优先级：**不需要你填搜索地址的源（洛雪脚本、内置聚合搜索）在前，自建协议源在后**。
搜索面板按源分组，组的先后就是它；取址时「同分取先出现者」、歌单导入与加密补档的择优也都按这个顺序。

为什么这样排：自建协议源通常是兜底——可能是你一个人的服务、只给一档地址，而脚本源能拿到更高的档位。
别家能搜到的同一条录音，优先用别家的地址。**同级**（同为协议源或同为脚本源）才按设置里的音源顺序。

这条顺序只管「同一首歌该用哪条搜索结果」，不改变「按 id 取址」：曲目已经定了归属时，
仍然向它自己那个源要地址（见下文「单曲取址」），不会因为别的源排得靠前就换源。

## aurora 音源服务

填一条服务地址即可，端点优先读服务端的自描述（`GET {服务地址}/` 响应里的 `endpoints`），
读不到按默认路径组装；密钥可直接写在链接里（`https://host?key=xxx`），「测试连接」会校验连通性与密钥。

| 能力 | 默认端点 |
|---|---|
| 搜索 | `/aurora?query={query}&quality={quality}&key=` |
| 单曲取址 | `/aurora/track?id={id}&quality={quality}&key=` |
| 歌词 | `/aurora/lyric?track={track}&artist={artist}&duration={duration}&key=` |
| 歌单解析 | `/aurora/playlist?url={url}&key=` |
| 推荐 / 榜单 | `/aurora/recommend`、`/aurora/toplists`、`/aurora/toplist` |

响应为 JSON 数组，或 `{results:[]}` / `{data:[]}` / `{songs:[]}` / `{list:[]}` 包裹。
搜索每项 `audioUrl` 必填，另有 `title` / `artist` / `album` / `duration` / `coverUrl`，
多音质用 `qualityUrls` 或 `url_128` / `url_320` / `url_flac`；歌词兼容
`syncedLyrics` / `lrc` / `lyric` / `plainLyrics`，全部音源未命中时回落内置 LRCLIB。
链接含 `{query}` 时按「接口模板」原样使用（该形态没有歌词与取址能力，那两项无从派生）。

单个音源的搜索预算是 **20 秒**：自建抓取后端冷启动实测能到 13 秒以上（首次请求要打上游搜索
再逐个补音质直链），预热后同一条请求 1 秒内返回。给足预算比把「冷」误判成「坏」更划算；代价是
真正失败的源要等满 20 秒才报错——多源并发时其它源的结果已到，不会互相拖住。

### 单曲取址：曲目已定就别按名重搜

曲目**已经定了**的时候（重启后的播放队列、导入歌单、音乐馆榜单与歌单条目按约定都不持久化
直链——直链几十分钟即过期），应用按**源内 id** 向 `/aurora/track` 取址，而不是拿
「歌名 + 歌手」重搜一遍：同名不同版本（变速版 / 翻唱 / DJ 版 / Live）按名匹配时与目标
同分，会串到别人的录音——元数据、时长、歌词都是原唱，播出来却是另一条（实测：《雨天》
汪苏泷 274s 的原唱被判给「雨天 (变速版)」115s 那条，界面显示 4:34、播放条显示 1:55）。

```json
{ "songmid": "002A97IJ2D6KYA", "found": true, "reason": null,
  "track": { "songmid": "002A97IJ2D6KYA", "title": "雨天", "artist": "汪苏泷", "duration": 274 },
  "results": [ { "audioUrl": "…", "quality": "128", "qualityUrls": { "128": "…" } } ],
  "quality": { "requested": null, "effective": "128" } }
```

- 应用只认 `id` 与 `results[0].audioUrl`，其余字段（`songmid` / `quality` / `qualityUrls` /
  `coverUrl` / `duration` / `track`）全部可选：实现了就回填，不实现也能用。
- `found=false`（`reason=not-found`）表示源端没有这条 id；`found=true` 而 `results` 为空表示
  有这条曲目但取不到直链（无权益等）。两种失败都让应用**回落按名搜索**，所以老服务端不实现
  这个端点只是回到旧路径，不会播不出来。
- 搜索与歌单响应里带 `songmid` 时，应用会把它存成曲目的源内 id（缺省回落条目 `id`）；
  取址时若遇到历史形态的 `<来源 id>-<id>`（早期搜索条目把来源拼进了 id）会自动剥前缀，
  但新服务端回填 `songmid` 才是正路。

## 洛雪音源脚本

可直接使用[洛雪音乐](https://github.com/lyswhut/lx-music-desktop)（桌面版 / 手机版）的用户自定义
音源脚本：添加脚本链接（GitHub Raw、jsDelivr 或自建托管均可），源码不落库。脚本在客户端沙箱内
执行：`document` / `navigator` / `location` / `localStorage` 与 Node 标识一律置为 `undefined`，
网络请求只能经宿主的 `lx.request` 转发，拿不到宿主配置、数据库与文件系统接口。

绝大多数脚本只实现 `musicUrl`、没有公共搜索接口（协议里压根没有 search 动作），因此
**搜索仍走你自己的搜索音源，脚本负责取址**；一条能搜的源都没有时，由内置「聚合搜索」兜底
（见下一节）。
别的音源搜到的曲目在播放/下载时会**先**请脚本源按源内 id 现取直链（取到就用它，含脚本能给的
音质与封面）；取不到时（脚本报错、地址不可播放、平台对不上）**静默回落**到曲目原有地址或按名
搜索 —— 取不到只是白试一次，不会让歌播不了。

平台归属**默认按曲目已有的播放地址自动识别**（QQ `*.qqmusic.qq.com`、酷我 `*.kuwo.cn`、
酷狗 `*.kugou.com`、网易 `*.163.com` / `*.126.net`、咪咕 `*.migu.cn`），所以正常情况下
**不需要**给脚本源配置任何平台。内置聚合搜索搜出来的曲目没有任何播放地址、域名无从推断，
平台由曲目数据自己标注（`trackRef.meta.platform`），同样不用你配。只有当你的音源服务返回的是
自己的中转地址、域名认不出平台时，才需要在脚本源上「限定平台」补一句；限制写错也只是取不到。

交给脚本的平台标识按洛雪约定映射（酷我 `kw` / 酷狗 `kg` 用 `hash` | `songmid`；QQ `tx` / 网易 `wy`
用 `songmid`，网易另认 `id`；咪咕 `mg` 用歌名 + 歌手）。取址**按需**触发：搜到的条目只有元信息，
播放或下载时才取直链回填队列，不写库也不落盘；脚本源没有歌词能力。

桌面端拉取脚本源码走 Electron 的网络栈（`net.fetch`），因此吃**系统代理**；只在 shell 里设的
`http_proxy` 之类环境变量对它无效。填 `raw.githubusercontent.com` 的链接在国内通常需要开系统代理，
或改用镜像地址（`ghproxy.net` 前缀、jsDelivr）。

## 内置聚合搜索（搜索兜底）

洛雪脚本协议里**没有搜索动作**（只有 `musicUrl` / `lyric` / `pic`，洛雪自己的搜索也走客户端
内置接口），所以「只配了一条脚本」的人搜索框里永远搜不出东西，而且不会报错 —— 插件按设计
返回空数组。内置的「聚合搜索」插件（设置 → 插件，可停用）补的就是这一段：
**软件负责找到歌，你的脚本负责放出歌**。

- **什么时候跑**：配好的音源跑完一轮、**一条结果都没有**时才跑。主源有结果时它一次请求都不发，
  不给正常搜索加延迟。「脚本到底会不会搜」在配置里看不出来（能力藏在脚本里），只能按结果判定。
- **搜什么**：并发查 QQ 音乐 / 酷我 / 网易云 / 酷狗 / 咪咕的公开搜索接口，拿回元信息
  （歌名、歌手、专辑、时长、封面、平台自报的可用档位），五家结果交错排列，第一屏就能看到
  不同平台。结果行的来源显示平台品牌名，而不是「聚合搜索」。
- **不内置取址**：直链仍由你的脚本在播放时现取（按 `trackRef.meta.platform` 认领平台），
  换平台直链要逐平台维护签名与加密，上游一改版就集体失效 —— 那是脚本该干的活。
- **只交能播的**：没有脚本源，或脚本源「限定平台」认领不到该平台（例如脚本只认酷我，
  而这条是 QQ 音乐的）时，这些条目**不会上屏**：宁可回「没找到」，也不给点了播不了的诱饵。
- 插件被停用后兜底完全不跑。

## WebDAV 媒体库（桌面端）

与在线音源不同，这是入库的持久曲库来源：配置服务器地址、账号与口令，测试连接后扫描入库。
口令仅存本机；移除来源会连同其曲目一起从曲库删除（远端文件不受影响）。

> 应用不内置、也不推荐任何源站。
